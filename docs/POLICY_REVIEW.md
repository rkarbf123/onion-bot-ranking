## 공개 전 확정할 사항

1. 개인정보처리자의 실제 명칭, 시행일, 문서 게시 위치와 서비스 URL을 기입한다.
2. 처리별 법적 근거와 필요한 개별 동의·안내 절차를 정한다. 서버 관리자의 설치를 구성원 전체의 동의로 취급하지 않는다. 공개 랭킹의 근거는 내부 XP 처리와 분리해서 확인한다.
3. 각 자료의 보유기간을 정하고 실제 파기 절차를 마련한다. 현행 코드에 없는 “시즌 종료 시 완전 삭제”, “탈퇴 시 자동 삭제”, 임의의 30일·90일 보관 약속을 쓰지 않는다.
4. 호스팅 제공자, GitHub 저장소·Pages의 실제 공개 상태, 클라우드 백업과 PC 동기화를 확인한다. 작업 경로가 OneDrive 아래에 있다는 사실만으로 동기화 활성 여부가 확인되는 것은 아니다. 위탁·제3자 제공·국외 이전에 해당하는 경우 관련 고지와 필요한 절차를 구체화한다.
5. 삭제·처리정지 요청의 담당자, 본인 확인, 처리 기한 및 삭제 대상 점검 절차를 정한다. 공개 제외와 전체 삭제를 구분한다. 복원으로 삭제된 사용자가 되살아나거나 이후 활동으로 즉시 재등록되지 않도록 하는 운영·기술 조치도 필요하다.
6. Git 이력·외부 캐시·이미 게시된 Discord 응답의 처리 범위를 정한다. 현재 파일 한 개의 수정만으로 모든 복제본이 없어졌다고 안내하지 않는다.
7. 실제 적용한 접근 통제와 저장·백업 보호 조치를 확인한다. `.gitignore`나 SQLite 트랜잭션을 암호화·접근 통제 완료의 근거로 사용하지 않는다.
8. 법정대리인 동의가 필요한 아동의 개인정보 처리에 대한 운영 방침과 확인 절차를 확정한다. 현재 코드에는 연령 검증·동의 수집 UI가 없다.

초안 작성 자체로 위 조치가 구현되거나 웹사이트에 게시된 것은 아니다. 운영 DB·공개 저장소·실제 배포 설정은 변경하지 않았다.
